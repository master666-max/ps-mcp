# 01 连接与安全（机制层）

标注体系同 SKILL.md。【✓实测】均发生于 2026-09-19（探针在 `agent-mcp-skill-PS/_probe/`，
可复跑）。通道定案与降级逻辑见 docs/decisions D3/D5。

## 1. COM 通道（S 模式主通道）【✓实测】

- ProgID `Photoshop.Application`（版本化 `.200`），CLSID `{2682BB05-0A88-430F-8614-EE4E60E6D916}`，
  LocalServer32=`Photoshop.exe /Automation`——注册表结构 2026-09-19 实查健康；
- PowerShell 侧：`$app = New-Object -ComObject Photoshop.Application`；PS 已运行时连接
  0.0s（附着活动实例）；未运行时 COM 冷启动【✗待实测】——SOP 一律先 Start-Process
  等就绪（约 12s）再做启动模态扫描，再连接；
- `$app.DoJavaScript($js)`：返回 JSX 末表达式的值；对象用 `.toSource()` 序列化；
  防御写法=每字段 try/catch（缺属性返回 undefined 字符串而不是炸整脚本）；
  `app.systemName`/`app.language` 在 27.10 COM DOM 不存在【✓实测】——别信旧字段清单；
- `$app.Quit()` 0.0s 正常退出【✓实测】；单实例+串行队列预设（多开行为【✗待实测】）；
- 沙箱无关：本 harness 的 Bash 沙箱内外 COM 行为一致【✓实测】。

## 2. 启动模态扫描与处置（当日核心发现）【✓实测】

**启动期可见模态框会阻塞 COM 类厂激活**：PS 冷启动带「暂存盘空间不足」警告时，
`New-Object` 稳定失败 `0x80080005 CO_E_SERVER_EXEC_FAILURE`（8 次重试 3 分钟不变；
ROT 直连同样失败；注册表健康、提权态正常——排除其余解释；WM_CLOSE 弹窗后 0.0s 即连上）。
证据链全文见 docs/research-ps-scripting.md §2。

连接 SOP（ps_connect.ps1 已内置）：
1. 枚举 PS 进程可见顶层窗口（EnumWindows，IsWindowVisible 且有标题）；
2. 主窗口之外的弹窗逐个记标题并报告——**先报告再处置**，处置分三档：
   a. **WM_CLOSE**：警告类弹窗（如暂存盘警告）等价于确认，先试这个【✓实测有效】；
   b. **截图+坐标点击**：弹窗是 Adobe 自绘容器（DroverLord/OS_ViewContainer），UIA 树下
      无按钮元素【✓实测】，PrintWindow 截图 → 人工辨认按钮位置 → SetCursorPos+点击
      （探针 `_probe/click_ok.ps1`）；
   c. **请用户手点**：a/b 都不行时明说"这一下必须人点"（A7 边界），不许静默假装能自动；
3. 处置后重扫确认弹窗消失，再连接。

**为什么 displayDialogs 防不了它**：`displayDialogs = DialogModes.NO` 只抑制脚本运行中
的操作弹窗；启动期模态出现在任何脚本之前（D1，docs/decisions）。

## 3. 错误三形态（PS 版）

| 形态 | 样例 | 对策 |
|---|---|---|
| 报错 | 无文档时 `app.activeDocument` 抛"没有这种元素"【✓实测】 | try/catch 包裹，错误串进 report，即停 |
| 静默失败 | profile 不匹配不报错只偏色【△文献】；智能对象缩放栅格化无提示损质【△文献】；写调用失败回 False/无异常【△文献】 | 逐调用查返回值进 report；profile/重采样参数显式声明；G0/G3 机验 |
| 卡死 | 启动期模态阻塞 COM（0x80080005）【✓实测】；batchPlay 描述符错弹模态框【△文献】 | §2 扫描处置；单脚本 ≤20s 拆步；卡死先枚举可见窗口 |

**卡死恢复 SOP**：① 跑窗口枚举找模态（§2）→ 处置；② 无模态则查进程 CPU/响应态，
无响应超 60s → 请求用户决定是否杀进程（杀进程=状态损失，须用户确认，重跑前先盘点
核对铁律 4）；③ 重试前只读盘点对账，防重复执行。

## 4. 源文件保护（第一铁律的通道面）

- 打开用户文件用 `app.open(File(path))`【△文献】；打开后第一步永远是 duplicate 或
  另存 AGENT_ 副本（02 分册 §2）；
- 用户文档关闭一律 `close(SaveOptions.DONOTSAVECHANGES)`——用户的文档状态以磁盘
  文件为准，agent 无权改写内存态落盘；
- 磁盘源文件：脚本永不写源路径；`File.saveAs`/`exportDocument` 目标必须在声明过的
  AGENT_ 输出目录内（白名单，铁律 5）。

## 5. F 模式：JSX 文件总线（兜底通道）【✓实测：命令行触发链路（0.6.1）】

触发条件：进程在而 COM 连不上（模态不可程序化处置/COM 被策略禁用）。链路实测：

1. agent 把任务脚本写到声明目录：`<AGENT_输出目录>/PSCP_<序号>_<任务名>.jsx`；
2. **触发【✓实测】**：`Photoshop.exe <script.jsx>` **冷启动即可**——当日实测 16 秒完成
   启动+脚本执行+report 落盘；中文/全角/空格路径不碍事；注意 `$.fileName` 返回
   **URI 编码**形态（解码后再比对路径）；
3. JSX 内用 `File.write` 把 report JSON 落盘到声明输出路径【✓实测】；
4. agent 读结果文件回读——读不到先查路径，不盲目重写；
5. 一次会话合并同段工作进一个脚本（每次触发有启动/点击成本）；脚本命名带序号；
6. 菜单触发（文件 > 脚本 > 浏览，zh_CN 菜单名【△文献】）仍为用户可选路径【✗未测】。

**场景边界（F-15）**：F 模式的存在意义是"COM 被阻时的兜底"，但**启动模态在场时
命令行脚本是否被执行未测**——若模态同样阻塞脚本，则该场景下 F 兜底不成立（降级为
"用户手点模态后 F 可用"）。ps_connect 的模态扫描先于一切，实际会话不受影响。

F 模式拥有与 S 模式同级的协议纪律：同一五段式、同一 report 契约、同一白名单。

## 6. UXP 预留接口（默认不启用；契约、启用条件与安全边界）

**用户裁决（D11，2026-09-19）**：默认通道=ps-mcp 的 COM 直连（S 模式）；UXP 作为
**预留第三通道**挂契约不实现。任何第三方 MCP 服务器（loonghao/adb-mcp）不作为默认
管道引入（D6/D10 维持）。

**预留的契约——通道可换，协议不变**。未来若启用 UXP（自建面板或临时借用 adb-mcp
面板做验证），以下不变量必须原样保留，通道差异只在适配器内消化：

1. 铁律 1-7 与四门（G0/G1/G3/G4）照常适用：源文件只读、AGENT_ 副本、破坏性操作前
   落盘快照、导出白名单、实看义务——这些是**通道无关**的；`displayDialogs` 等 COM
   特有项由 UXP 侧等价物替代（通道特有项不进协议层）；
2. **report JSON 仍是文档状态的唯一可信投影**：UXP 的 batchPlay/事件结果必须折算进
   同一 report 字段（文档清单/图层树/操作返回值/快照与产物路径），禁止另造投影格式；
3. 五段式脚本骨架照用（参数区→幂等准备→helper→操作→输出），宿主从 COM 换成面板内 JS；
4. 输出与实看链路不变：仍导出 PNG 到声明目录、仍 Read 实图核验。

**启用触发条件（任一出现才评估；UXP 通道默认不启用，启用须用户明示）**：
1. F-9 实测证明 AI 生成工具必须 batchPlay/进程内才可调（COM DOM 不可达）；
2. 工艺库条目确认依赖 COM DOM 不可达的能力（描述符级操作/事件监听）；
3. COM 通道被环境禁用且不可恢复（策略/持续性 0x80080005 类阻塞）。

**启用路径**：自建最小 UXP 面板（长期正解，代码与供应链可控）＞临时借用 adb-mcp
面板（只作快速验证；第三方代码进 PS 进程属供应链考量，不作常驻）。

**启用前置实测**（research §6 #15）：UXP Developer Tool 安装链路 / 开发者模式 /
面板 Load 与驻留 / UXP 文件系统权限模型。

**禁止**：静默切换通道；把第三方面板当默认管道常驻；为"省一步连接"绕过本契约。
新建扩展一律 UXP 不碰 CEP（生态结论不变，docs/research §4）。
