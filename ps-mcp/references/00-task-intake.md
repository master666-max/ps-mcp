# 00 任务 Intake（入口层）

两段式 intake：先问"有什么"再问"要什么"。感知前提+降级三态（✓/△/N/A）贯穿全部
intake 问答——用户没给的输入标 △ 并问，禁止假称已知、禁止静默跳过。

## 0. 输入端路由（第 0 步：先判用途分支，再进两段式）

三信号源（文件特征/用户话术/产物要求）判主分支。判定依据全文见
[docs/research-use-case-branches-20260919.md](../docs/research-use-case-branches-20260919.md)；
蒸馏版判定表：

| 判向 | 特征速查 | 路由后果要点 |
|---|---|---|
| A 照片修图（核心） | 单张照片/RAW；"修/调/抠/去瑕疵/锐化/统一调色" | 全门标准走；档位=轻修/标准/合成级 |
| B 创意合成 | 多素材+底图；"合成/拼/融合/放进" | G1 最重；每次置入/融合前快照；源只读压力最大 |
| C 平面设计 | .psd 模板+文字层/画板；"做/排/全套尺寸/换文案" | 文字机读 F-10 落地前**限结构操作**；印刷转换先快照 |
| D UI 切图 | 设计稿+资产命名图层；"切图/@2x/导出资产" | G1 轻量化=首件确认；G3 尺寸/命名对账；基本只读 |
| E 批处理 | 目录级文件集；"这一批/统一/每张都" | **首件试产走全门**再批量；破坏性放大器纪律 |
| F 绘画插画 | "画/手绘/插画" | 画笔笔触与手绘属于人的领域，agent 不代画；只承接画布/图层结构/导出等结构操作 |
| G AI 生成 | "AI 补/AI 扩/AI 放大/调和" | 先探 F-9 脚本可达性；积分成本先向用户确认；每次生成为一方案走 G1 |
| H 边界 | 3D/视频剪辑/RAW 编目/矢量编辑 | 不在本 skill：3D→blender-mcp；剪辑→达芬奇；RAW 编目→Lightroom；矢量→Illustrator |

**路由规则**：判不准不猜——分支确认并入第一段第一问；判准了开工消息仍要**报分支
与后果**（门配置/档位/边界），用户可当场纠正；防护取重（按破坏性更强的分支配门与
快照）。不在本 skill 的分支一律明示并指路，不静默承接（指路时说明版本事实或工具
属性依据）。

**混合用途检测**：判出主分支后，主动扫描任务是否还含其他分支的实质工作。信号：
①动词含多个工艺动作（"修完顺便切图/调完再批"）；②产物含多形态（"成图+资产包/
印刷稿"）；③文件集异质（照片+设计稿混交）。检出 → **开工消息列【主分支】+【次分支】
清单**并显式拆分声明；次分支工作占比 ≥40% 或有独立交付物时升为并列主分支；门配置
取涉及分支的并集（防护取重）。

**路由后果之一：读工艺库（两层，候选取用三级递进）**。判出主分支（含混合检出的
次分支）后读取 [craft-library.md](craft-library.md)：**清单项层**（实战验证）直接
生效；所有任务都读 **X 节**（跨分支条目，P1 由规则指定）。**候选层取用三级递进**：
**L1 分层**——候选带 P1（核心常读）/P2（条件触发，条件在条目状态里）标，任务时只读
P1+命中条件的 P2，多数任务零重排；**L2 任务型组合缓存**——
任务型首次出现时排一次，结果写回组合缓存固化，同型任务直接复用不再排；**L3 运行时重排（兜底）**——仅新
任务型/条件全不命中/池跨 200 条时触发，可用 scripts/rerank_local.py 经本地 LM Studio
重排（不占对话上下文；Server 未开时由 agent 内判断兜底，不阻塞）。重排器只建议
P2 条件与顺序，P1 由治理指定。结果标注"候选，非强制"，**top-k 与理由进开工消息**；
争议条目引用时必须向用户明示"此处无社区共识"。候选 ≥2 次实战支撑后晋升清单项
（晋升前禁止当清单项执行）。

## 1. 第一段：有什么（盘点自答优先）

能靠盘点脚本自答的不问用户。先拿到文件路径（问一句"文件在哪"），其余用 G0 盘点自答：

| 问 | 自答手段 | 自答不了才问 |
|---|---|---|
| 格式/尺寸/模式 | 盘点脚本读文档与文件（02 分册 §4） | 文件打不开/格式罕见 |
| **视觉首察**：内容类型/处理目标的视觉特征（形态/颜色/透明度/范围/边界）/区域地图 | **Read 源图直接看**（多模态首察，第一段第一步）——输出"视觉发现清单"，方案假设从这里来 | 视觉判不定（如叠加层透明度无法目估）标 △ 问用户或用探针测 |
| 图层结构/图层数 | 盘点 report 图层树 | — |
| 色彩空间/profile | `colorProfileName` 机验【✓实测字段可用】 | 文档无 profile（未标记） |
| 智能对象清单 | 盘点 report（kind=SMARTOBJECT） | — |
| 源文件是否可覆盖读 | 磁盘只读盘点，永不写 | 文件被占用/只读属性 |

**必须问的**（盘点自答不了）：处理目的是什么（第二段）；多文件任务的文件清单与
命名规律；交付格式与落点（含是否允许 agent 建 AGENT_ 输出目录）。

## 2. 第二段：要什么（修图深度档定档）

- **轻修**：全局调整（曝光/色彩/裁剪/锐化），不动图层结构——预期单脚本 1~2 步；
- **标准**：+局部修整与图层操作（瑕疵/蒙版/调整层）——预期分阶段，每阶段 G1 对比；
- **合成级**：多素材/智能对象/复杂蒙版/融合——预期多阶段+快照密集。

定档后与用户确认（一句话复述任务+档位+输出落点）。具体工艺判据 03 分册待实战回填，
intake 只定档不定做法。

## 3. 问题池（首次接触必问清单）

1. 文件在哪？（路径，多文件给清单）
2. 要什么效果/修什么？（用户口头描述记原文，判断建立在 G0 实看之上不建立在描述之上）
3. 深度档：轻修/标准/合成级？
4. 交付格式与落点？（PNG/JPEG/PSD；AGENT_ 目录里哪个文件是最终交付物）
5. 有没有不可碰的东西？（用户图层/命名的组/特定智能对象——照收不猜，中文图层名
   原样进 report）

## 4. intake 输出形态（开工消息模板）

> 模式判定：S/F【原因】｜**视觉复述**：我看到的是…（G0 首察一句话结论）｜
> 盘点：N 个文档（尺寸/模式/profile/图层数，逐项）｜
> 任务复述：…｜深度档：…｜AGENT_ 输出目录：<声明路径>｜快照计划：…
> 不确定项标 △ 等用户确认后才动笔。
