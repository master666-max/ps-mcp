# Photoshop 驱动手册（ps-mcp v0.1.0）

本手册驱动真实运行的 Photoshop。事实标注体系：【✓实测】=本机真机验证过；
【△文献】=官方/社区文档或同族经验，未本机复验；【✗待实测】=尚未验证，使用前先探。
首次实测任何【✗待实测】条目后必须回写标注。

## 0. 模式判定与连接自检（每次会话必做）

**两种运行模式，判定是一次性的、结果要报给用户：**

1. 探进程：`Get-Process Photoshop`（或 tasklist）。
   - 没运行 → `Start-Process` 启动并等主窗口就绪（本机实测约 12 秒）；
2. **启动模态扫描**（COM 之前必做）：枚举 PS 进程的可见顶层窗口，主窗口之外还有可见
   弹窗（如「暂存盘空间不足」）→ 先处置再连接（处置 SOP 与当日实证见 01 分册 §2）；
3. 跑 `scripts/ps_connect.ps1 -JsPath <探针jsx>`：
   - **OK-CONNECT → S 模式**（COM 直连）：一切操作经 `DoJavaScript(jsx)`，输出走
     返回串；建档→导出→回读探针通过即同时完成激活态运营级判定（D4）；
   - **进程在而连不上 → F 模式**（JSX 文件总线）【✗待实测】：任务脚本落盘为 .jsx，
     经 `Photoshop.exe <script.jsx>` 或用户菜单触发，JSX 内 `File.write` 落盘 report
     JSON，agent 用读文件代替读返回串（同达芬奇 F 模式纪律，01 分册 §5）；
4. **自检结果不得静默消费**：模式判定 + 原因（模态阻塞/未启动/F 模式边界）必须报给
   用户，随任务开场消息一并说明。UXP 为**预留第三通道**（默认不启用，启用条件与
   通道契约见 01 分册 §6 与 docs/decisions D11）。

## 1. 七条铁律（每条都有出处）

1. **源文件只读——不覆盖、不另存到原路径、不 flatten 用户文档、不删用户图层**。
   磁盘上的 .psd/图像是圣域（手绘图层不可再生）；内存中的用户文档同样只读：
   不合并、不栅格化、不改名、不删图层。删除/合并/栅格化类操作仅允许作用于 AGENT_ 副本。
2. **一切编辑在 AGENT_ 前缀副本文档上进行**：`document.duplicate()` 得到副本后改副本名
   为 `AGENT_<任务>_v1`，或打开源文件立即另存 AGENT_ 副本再动笔；输出文件一律进
   声明过的 `AGENT_` 输出目录。开工先盘点（G0）。
3. **破坏性操作前 AGENT_ 版本化另存落盘**（PSD 快照 = 达芬奇三重快照的对应物）：
   快照路径先声明后执行，版本号递增不覆盖；脚本内 `suspendHistory` 打组历史只是辅助，
   suspendHistory 不能替代落盘快照（历史栈关文档即清零，脚本撤销不可靠）。
4. **report JSON 是文档状态的唯一可信投影**：图层树（名/类型/可见性/锁）、尺寸/模式/
   分辨率/profile、历史栈深度、操作返回值——全部来自脚本回传，禁止凭记忆或想象描述
   文档状态。能写成数字的判断全部数字化。
5. **输出路径白名单**：只写声明过的输出路径，导出前检查目标不存在；永不覆盖任何
   已存在文件（含用户文件与此前 AGENT_ 产物——要新版本就递增版本号）。
6. **脚本首个状态调用必须是 displayDialogs = DialogModes.NO**——操作期模态弹窗是
   自动化卡死之源（启动期模态防不住它，另见 §0 第 2 步与 01 分册 §2）。
7. **每个写调用检查异常与返回值**：PS 的静默失败家族——profile 不匹配不报错只偏色、
   智能对象缩放栅格化不提示损质、batchPlay 描述符错可能弹模态框【△文献】——
   所有 Set/Apply/Add 类调用逐个进 report；异常即停，报告现场，不猜测续跑。
8. **视觉实看贯穿全流程，判定分辨率不足=没看**：模型有原生多模态感知——每阶段必须
   定义并执行视觉检查（看什么/多大分辨率/判什么），实看留证据（瓦片文件+实看清单入
   report）；质量判定必须在**缺陷可见的分辨率**上做出，降采样视图只作导航；看不清
   标 △，禁止以分辨率不足的视图宣告质量。**△ 出口**：视觉通道不可用（无图像输入/
   图像服务失败/内容超分辨率极限）时，该阶段视觉义务标 △+原因，降级为数字通道+用户
   确认——△ 是合法出口，静默省略不是。

## 2. 阶段门（修图管线——数字与视觉双通道）

| 门 | 数字通道 | 视觉通道 | 判据形态 |
|---|---|---|---|
| G0 文档盘点门 | 源文件清单+文档盘点（图层树/尺寸/模式/profile）入 report | **视觉首察**：全图实看→视觉发现清单（内容类型/处理目标特征[形态/颜色/透明度/范围]/区域地图/方案假设） | 数字+实看 |
| **Px 过程检查点**（每个写操作后） | 操作返回值进 report | **就地 1:1 实看**：操作区前后并排小瓦片；异常当场修正；同一操作 ≥2 次修正失败→升 G1 交用户 | 实看 |
| G1 方向门 | — | 前后对比图+方法说明交用户过目——改方向最便宜的时刻 | 用户裁决 |
| G3 技术一致门 | 尺寸/模式/分辨率/profile 与声明一致；步骤对账 | **成品视觉检验**：沿处理区 1:1 分块瓦片全长实看（CL-X-08） | 数字+实看 |
| G4 交付门 | 导出文件存在、大小>0、尺寸核对 | **展示包**：对比图+特写对+实看瓦片清单交用户 | 数字+实看 |

门不适用标 N/A 并附理由，禁止静默省略整行；交付时输出**验收宣告行**逐门打勾，
并附**实看清单**（瓦片/对比图文件名清单——存在性可机查，看过才可声明）。

## 4. 导出实看义务（全家族最强验证闭环，别浪费）

PS 的一切皆可导出实看：整图低分辨率 PNG（阶段 checkpoint）、局部区域裁剪放大
（每轮小步）、前后对比并排图（G1）——导出到 AGENT_ 目录后用 Read 读图进上下文。
剪辑 100% 视听同理，修图 100% 像素：**任何"已修好/已完成"声明必须有导出实看为证**；
文件存在、尺寸对（存在性≠看过）。色彩判断必须连同 profile 声明一起看（同一张图在
不同 profile 下偏色不同，裸眼判断前先核对 profile）。

## 5. 修图深度档（intake 时与用户确认）

**轻修**（全局调整：曝光/色彩/裁剪/锐化，不动图层结构）→ **标准**（+局部修整与
图层操作：瑕疵/蒙版/调整层）→ **合成级**（多素材/智能对象/复杂蒙版/融合工艺）。
各档的具体工艺判据在 03 分册**待实战回填**——档位可以选，工艺内容不预写不臆测。
低于所选档的深度属于偏离，须声明留痕。档位语义对修图族（照片/合成）完全适用；
其他分支（设计/切图/批处理/绘画/AI）在 intake 时按分支定义等价档位
（00 分册 §0 路由后果表），不许拿修图档位硬套。

## 6. 恢复 SOP 摘要（细则在 01 分册）

- 脚本超时/卡死：S 模式单脚本工作量控制在 ~20 秒内（大 PSD 再拆小），长任务拆步+
  每步导出留痕，防"用户以为死了"；batchPlay 错误可能弹模态框【△文献】——卡死先查
  可见顶层窗口（01 分册 §2 同款扫描）。
- 重复执行风险：超时后操作可能已生效——重试前先跑只读盘点核对状态（铁律 4 对账）。
- COM 连接堆积：COM 是同一活动实例的进程内调用，无渲染队列；并发需求一律串行
  （单实例+队列预设【✗待实测多开行为】）。

## 7. 协议摘要

- **五段式脚本骨架**：参数区（输出路径/操作清单，全部先声明）→ 幂等准备（AGENT_ 副本
  get-or-create、快照）→ helper → 操作（逐调用进 report）→ 输出（S 模式 JSX 末表达式
  `.toSource()` 经 COM 返回；F 模式 `File.write` 落盘 report JSON）。
- **report 最小字段**：模式、文档清单（名/尺寸/模式/profile）、图层树摘要（大文档按组
  分页）、本次操作逐项结果、快照与产物路径、错误与 N/A 项、**实看清单**（瓦片/对比图
  文件名——与文件系统互证）。
- **验收宣告行**：交付消息必须含 G0/G1/G3/G4 逐项结果（✓/△/N/A+理由）。
- 版本语义与治理（指纹/台账/发布四查）见 `evals/`；修订语义定义时全包 grep 同步。
